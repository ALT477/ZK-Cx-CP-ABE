Service provider mode
IoT → Proxy
Sensors collect vitals; mobile device encrypts under CxABE policy and sends to proxy.
Proxy → Fog
Proxy performs lightweight re-encryption and key management; forwards to nearest fog node.
Fog → Blockchain
Fog stores ciphertext, hashes metadata, submits PoA transaction. Block receipt confirms registration.
Service consumer mode
Specialist → Fog
Authorized specialist submits access request with attributes; fog records access-intent on-chain.
Smart contract check
ABE smart contract verifies attributes vs. policy tree. PERMIT or DENY logged immutably.
Fog → Client decrypt
Fog performs partial decryption (CT→CT'). Client completes decryption with private ABE key.
System components & roles
Patient + Sensors
Wearable IoT devices collecting ECG, BP, temperature, SpO₂, GPS. Encrypts and uploads to fog.
Proxy (delegator)
Re-encrypts ciphertexts, manages re-encryption keys, authenticates sensors, prevents raw data exposure.
Fog server (validator)
PoA validator, partial decryptor, policy matcher. Reduces latency by processing near the data source.
Cloud server
Centralized archive for patient accounts, transactional metadata, and geolocation of fog servers.
Blockchain (PoA)
Immutable ledger for access logs, smart contracts for ABE key management, credit-based trust model.
Certificate Authority
Fully trusted CA issues digital certificates and attribute-based secret keys to all participants.

Smart contract · Dolev-Yao adversary model
Unauthorized access attempt
Adversary with mismatched attributes attempts to read patient data — smart contract DENY logged immutably on-chain
Adversary profile
Required policy:
Role=Cardiologist & Dept=HeartClinic & City=Setif
Attack log
✕ Access DENIED — DENY event logged immutably on-chain. Attacker cannot modify or erase this record.
Threat model — Dolev-Yao adversary
Adversary capabilities
Full control over communication channel. Can eavesdrop, replay, inject, tamper, and perform DoS attacks.
What the adversary cannot do
Break cryptographic primitives (ECC, hash functions). Forge a valid attribute certificate from CA.
IoToDChain defense
Smart contract verifies attribute set against policy tree. Fog never decrypts without PERMIT. All denials are immutable on-chain.
Credit-based blacklisting
Repeated failures reduce device credit score. Blacklist entry written to ledger — blocks all future access attempts.

PoA consensus protocol
① Client → Fog (proposer)
Client submits transaction to fog node acting as block proposer.
② Proposer signs block
Proposer creates, signs block with certificate, broadcasts to other validators.
③ Validators vote
Other fog nodes verify and vote. Quorum = 2/3 validators must attest.
④ Block committed
Block appended to ledger. Receipt sent to client. Instant finality — no mining.
